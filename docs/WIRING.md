# 로봇 배선 — 장치별 역할과 핀

로봇(Jetson) 쪽에서 실제로 쓰는 장치만 다룹니다. 스테이션(급수 펌프,
송풍 팬 등)은 `Raspberry-master` 브랜치 담당이라 여기 없습니다.

미확정·미배선 상태인 부분은 **★**로 표시했습니다. 실측 전 값을 코드로
단정하지 않는다는 팀 원칙([`CODE_STYLE.md`](CODE_STYLE.md)) 을 배선에도
그대로 적용한 것입니다.

```
   DP  ─────────────┤ 7인치 LCD (표정)         │

   USB ─────────────┤ ESP32 (시리얼)           │
                    └───────────┬─────────────┘
                                │ USB (급전 + 시리얼 명령)
                    ┌───────────▼─────────────┐
                    │   ESP32                 │   모터 실시간 제어
                    │                          │
   PWM ×2 ──────────┤ BTS7960 #1 (좌)          │
   PWM ×2 ──────────┤ BTS7960 #2 (우)          │
   디지털입력 ×4 ────┤ 엔코더 A/B (좌/우)       │
                    └───────────┬─────────────┘
                                │
                    ┌───────────▼─────────────┐
                    │ BTS7960 ×2               │   모터 드라이버
                    │  M+/M− → FIT0403 좌/우   │
                    │  B+/B− → 3S 배터리       │

      3S 배터리(BMS) → 퓨즈 → BTS7960 → 모터
      ⚠️ 두 팩의 GND는 반드시 한 가닥으로 연결 (플러스는 절대 금지)
```

## Jetson Orin Nano

**역할**: 카메라·라이다로 주변을 보고, 센서를 읽고, 서버와 MQTT로 통신하고,
화면에 표정을 그리고, ESP32에 이동 명령을 내립니다.

| 연결 | 대상 | 비고 |
|---|---|---|
| USB | LiDAR (YDLIDAR X4 Pro) | `/dev/ttyUSB*`, ESP32와 시리얼 번호로 구분 |
| USB | 카메라 (BRIO 100) | `/dev/video_cam` (udev 규칙으로 고정). UVC 라 `/dev/video*` 노드가 둘 이상 생겨 번호로는 못 고릅니다 |
| USB | 사운드카드 → PAM8403 앰프 → 8Ω 스피커 | 확인: `aplay -l` (아래) |
| USB | ESP32 | `/dev/ttyUSB_ESP32` (udev 규칙으로 고정) |
| DP (액티브 어댑터) | 7인치 LCD 1024×600 | 젯슨에 HDMI 단자 없음. 패시브 어댑터 동작 안 함 → [`JETSON_DISPLAY.md`](JETSON_DISPLAY.md) |
| I2C 버스7 (40핀 헤더 3번=SDA, 5번=SCL) | BH1750, ADS1115, INA226 | 세 칩이 같은 버스를 병렬 공유, 주소로 구분 |

**LiDAR·ESP32가 둘 다 `/dev/ttyUSB*`로 잡히는 문제**: 둘 다 CP210x 칩이라
꽂는 순서에 따라 번호가 바뀔 수 있습니다. 시리얼 번호로 구분한 udev
규칙이 이미 있습니다 (`README.md` "USB 장치 이름 고정" 참고).

### 스피커가 안 들릴 때

소리가 안 나면 대부분 하드웨어가 아니라 **어떤 카드로 나가는지**의 문제입니다.
젯슨은 DP 출력에도 오디오 장치가 잡혀서, 기본 카드가 USB 사운드카드가 아니면
소리가 화면 쪽으로 나갑니다.

```bash
aplay -l                              # 카드·장치 번호 확인 (USB 사운드카드를 찾는다)
speaker-test -t wav -c 2 -l 1         # 기본 카드로 실제 소리
aplay -D plughw:1,0 어떤파일.wav        # 특정 카드로 강제 재생 (1 = 위에서 본 카드 번호)
amixer -c 1 sset 'PCM' 90%            # 볼륨 (카드마다 컨트롤 이름이 다름: amixer -c 1 scontrols)
```

기본 카드를 USB 사운드카드로 고정하려면 `/etc/asound.conf` 또는 `~/.asoundrc`:

```
defaults.pcm.card 1
defaults.ctl.card 1
```

`speaker_node`가 쓰는 재생 명령은 `potner_params.yaml`의 `speaker.audio_player`
(기본 `["aplay", "-q", "{text}"]`)입니다. 카드를 명시하려면 여기에 `-D` 를
넣으세요. 음성 대화 전체 흐름은
[`../voice-chat-server/README.md`](../voice-chat-server/README.md).

## ESP32 (DevKitC V4 / DOIT V1 겸용)

**역할**: 엔코더 신호를 하드웨어로 세고(리눅스는 이 타이밍을 못 맞춤),
모터 속도를 PID로 제어합니다. Jetson과는 USB 시리얼 한 줄로만 대화합니다.

| 핀 | 용도 |
|---|---|
| GPIO 25 | 왼쪽 모터 RPWM (BTS7960 #1) |
| GPIO 26 | 왼쪽 모터 LPWM (BTS7960 #1) |
| GPIO 32 | 오른쪽 모터 RPWM (BTS7960 #2) |
| GPIO 33 | 오른쪽 모터 LPWM (BTS7960 #2) |
| GPIO 34 | 왼쪽 엔코더 A |
| GPIO 35 | 왼쪽 엔코더 B |
| GPIO 36 | 오른쪽 엔코더 A (실크스크린엔 `SENSOR_VP`로 표기될 수 있음) |
| GPIO 39 | 오른쪽 엔코더 B (`SENSOR_VN`) |
| USB | Jetson (급전 + 시리얼 명령) |

**GPIO 34~39를 엔코더에 쓰는 이유**: 이 핀들은 입력 전용이라 실수로
출력으로 잘못 쓸 일이 없습니다. 대신 **내부 풀업이 없고 3.3V 가
한계**입니다.

**GPIO 0·2·12·15는 쓰지 않습니다** — 부팅 모드를 정하는 스트래핑 핀이라,
여기에 뭔가 물리면 보드가 부팅을 못 하거나 업로드가 안 됩니다.

**전원은 USB로만 받습니다.** 3S/4S 배터리를 ESP32의 `VIN`에 연결하지
마세요 — 온보드 레귤레이터가 과열하고, USB와 동시에 물리면 위험합니다.

## BTS7960 (모터 드라이버, ×2 — 좌/우 각 1개)

**역할**: ESP32의 약한 PWM 신호로 모터에 실제로 흐르는 큰 전류를
스위칭합니다. 이게 있어야 ESP32가 직접 모터를 구동하지 않아도 됩니다.

| 단자 | 연결 대상 |
|---|---|
| `VCC` | ESP32 5V |
| `GND` | ESP32 GND (배터리 GND와도 공통) |
| `RPWM` | ESP32 GPIO (좌: 25, 우: 32) |
| `LPWM` | ESP32 GPIO (좌: 26, 우: 33) |
| `R_EN`, `L_EN` | ESP32 3.3V (항상 HIGH로 묶음) |
| `R_IS`, `L_IS` | 연결 안 함 |
| `B+`, `B−` | 3S 배터리 (B+ 앞에 퓨즈) |
| `M+`, `M−` | FIT0403 모터 (좌/우 각각) |

**`R_EN`·`L_EN`을 반드시 HIGH로 묶어야 합니다.** 펌웨어가 이 핀을 건드리지
않아서, 안 묶으면 PWM을 아무리 보내도 모터가 안 돕니다. 3.3V에 묶는 이유는
ESP32가 꺼지면 드라이버도 같이 죽게 해서 안전하게 하려는 것입니다.

## FIT0403 (구동 모터 + 엔코더, ×2)

**역할**: 로봇을 움직이는 바퀴 모터입니다. 엔코더가 내장돼 있어 실제로
얼마나 돌았는지(오도메트리)를 알 수 있습니다.

| 선 | 연결 대상 |
|---|---|
| 모터 2가닥 | BTS7960 `M+`/`M−` |
| 엔코더 전원·GND | ESP32 3.3V/GND (실측 확인 완료) |
| 엔코더 A | ESP32 GPIO 34(좌) / 36(우) |
| 엔코더 B | ESP32 GPIO 35(좌) / 39(우) |

**엔코더 동작 전압 실측 완료.** ESP32 3.3V로 전원을 넣은 상태에서 손으로
축을 돌려 A 출력이 0↔3.3V로 정상 스위칭되는 것과, PWM 구동 중 틱 카운트가
정상적으로 올라가는 것까지 확인했습니다. 레벨 시프터나 저항 분압 없이
직결하면 됩니다.

**모터 선 구분법**: 6가닥 중 저항이 낮은(수 Ω) 한 쌍이 모터, 나머지
4가닥(전원·GND·A·B)이 엔코더입니다. 순서는 제품 배선표를 직접
확인하세요 — 표만 보고 단정하다 부품을 태운 적이 있습니다.

## I2C 센서 3종 (버스 공유)

Jetson의 I2C 버스 하나(버스 7, 40핀 헤더 3번=SDA·5번=SCL)에 세 칩이
병렬로 물립니다. I2C는 원래 이렇게 여러 장치를 한 버스에 물리도록
설계된 프로토콜이라, 주소만 겹치지 않으면 됩니다.

| 장치 | 주소 | 역할 |
|---|---|---|
| BH1750 | 0x23 | 조도 측정 → `plant/lux` |
| ADS1115 (16비트 4채널 ADC) | 0x48 | 토양 수분 센서(아날로그)를 디지털로 변환 → `plant/moisture`. **AIN0 한 채널만 사용**, 나머지 3채널은 비어 있음 |
| INA226 | 0x40 | 젯슨팩(4S) 배터리 전압 → 잔량 % → `battery/percent`. 전류도 잴 수 있는 칩이지만 지금은 전압만 사용 |

**INA226은 신호선과 전력선이 따로 갑니다.** 나머지 둘과 달리, I2C
신호선(SDA/SCL)만으로는 부족하고 **VBS(배터리 전압 측정 입력)를 배터리
+/− 라인에 직접 물려야** 전압을 잽니다.

★ **VBS가 아직 배터리 라인에 연결되지 않았습니다.** I2C 신호선은 이미
붙어 있어 칩 자체는 탐지되지만(`_probe()`가 찾아냄), 전압을 읽지는
못합니다. 배선 위치는 퓨즈 뒤(BTS7960으로 가는 라인이 아니라 4S 팩
쪽)가 아니라 **4S 팩의 +/−**입니다 — 잔량을 재는 대상이 젯슨팩이기
때문입니다.

**토양 수분 센서(정전식)**: I2C가 아니라 아날로그 출력이라 ADS1115의
AIN0에 물립니다. 실측 보정(공기 중 값·물속 값)이 안 되면 `plant_sensors`
가 값을 아예 발행하지 않습니다 — 가짜 값으로 엉뚱한 급수 임무가 뜨는 걸
막기 위한 것입니다.

## 전원

| 팩 | 대상 | 경로 |
|---|---|---|
| 4S 리튬이온 | Jetson | 직접 |
| 3S (BMS 내장 또는 별도 모듈) | 모터 | 퓨즈 → XT60 → BTS7960 |

- **두 팩의 GND는 반드시 한 가닥으로 연결합니다** (플러스끼리 잇는 것은
  절대 금지 — 단락됩니다).
- ★ 퓨즈는 **20A 지연형(slow-blow)** 을 씁니다. FIT0403 stall 7A × 2개
  동시 걸림(14A)을 견디면서 그 이상의 단락은 끊어주는 값입니다.
  배터리 쪽에 최대한 가깝게, +선에 직렬로 넣습니다.
- BMS가 배터리팩에 이미 내장돼 있는지(밖으로 2~3가닥만 나옴) 먼저
  확인하세요. 셀과 BMS 모듈을 따로 배선해야 한다면 밸런스 커넥터
  순서를 멀티미터로 확인한 뒤 연결합니다 (틀리면 셀이 단락될 수 있음).

## 지금 배선 상태 요약

| 장치 | 신호선 | 전력선 |
|---|---|---|
| LiDAR·카메라·스피커·화면 | 완료 (USB/DP) | 완료 |
| BH1750 | 완료 | 완료 |
| ADS1115 + 토양 수분 센서 | 완료 | 완료 (센서 자체는 실측 보정 전) |
| INA226 | 완료 (I2C) | ★ **미완 — VBS가 배터리 라인에 안 물림** |
| ESP32 ↔ BTS7960 ↔ FIT0403 | 완료 — 좌/우 PWM 구동·엔코더 카운트 실기 확인 | 완료 |

모터 쪽 배선에서 실제로 확인된 주의사항:

- **엔코더는 3.3V 직결로 정상 동작** — 레벨 시프터 불필요 (자세한 내용은
  `potner_firmware/README.md` 참고).
- **좌우 바퀴 속도 편차 측정 시 주의**: 워치독(0.5초) 때문에 명령을 한 번만
  보내면 가속 구간만 보게 돼서 편차가 실제보다 훨씬 크게(13~49%) 보입니다.
  0.2초 간격으로 반복 전송해 정상 상태에서 재야 정확합니다 (실측 편차 약 4~5%).
- **FIT0403 stall current는 7A(1개)** (데이터시트 확인). 두 바퀴 동시
  걸림이면 최악 14A — 그래서 퓨즈가 20A 지연형입니다.
- 모터 전류가 흐르는 선(B+/B−/M+/M−)은 **브레드보드에 올리지 않습니다.**
  브레드보드 접점은 1A 정도까지만 버팁니다. 나사 단자로 직접 연결하고,
  배터리 쪽 +선에는 인라인 퓨즈 홀더로 퓨즈를 직렬로 넣습니다.
- 모터 드라이버(BTS7960)의 `R_EN`, `L_EN` 핀은 **3.3V에 연결해야** 합니다.
  연결하지 않으면 PWM 신호를 보내도 모터가 돌지 않습니다.
