## 주의사항 — 먼저 읽어주세요

### 1. 모터 첫 배선 (다음에 할 큰 작업)

- 반드시 `Robot-feature/motor-bringup/349` 브랜치에서 시작합니다. 개루프
  명령과 확인 도구(`tools/motor_bringup.py`)가 이 브랜치에만 있습니다.
  바퀴 지름(60mm) 자체는 이미 `Robot-develop` 에 반영돼 있습니다.
- 349 는 `Robot-develop` 의 최근 커밋들을 받지 못한 상태입니다. 배선을
  시작하기 전에 `git rebase Robot-develop` 로 최신 상태로 맞춰두는 것을
  권합니다.
- 첫 회전은 개루프(`D` 명령)로 확인합니다. 폐루프(`V` 명령, 엔코더 값을
  보고 속도를 조절하는 방식)는 엔코더 배선이 잘못됐을 때 오차가 계속
  쌓여서 바퀴가 갑자기 최대 속도로 돌 수 있습니다. 개루프는 이 위험이
  없습니다.
- 바퀴는 공중에 띄운 채로 확인합니다. 배선 방향이 반대면 로봇이 책상
  아래로 떨어질 수 있습니다.
- BTS7960 의 `R_EN`, `L_EN` 핀은 3.3V 에 연결합니다. 연결하지 않으면
  PWM 신호를 보내도 모터가 돌지 않습니다. 첫 시험에서 가장 자주
  걸리는 부분입니다.
- 모터 전류가 흐르는 선(B+/B−/M+/M−)은 브레드보드에 올리지 않습니다.
  브레드보드 접점은 1A 정도까지만 버팁니다. 나사 단자로 직접 연결하고,
  배터리 라인에는 5A 퓨즈를 넣습니다.
- 배선 전에 멀티미터로 먼저 확인합니다: 배터리 팩 전압(11.1~12.6V),
  FIT0403 의 모터 선 한 쌍(저항이 수 옴으로 낮게 나옵니다), 엔코더가
  3.3V 에서 정상 동작하는지 (ESP32 의 GPIO 34~39 는 3.3V 이상을 견디지
  못합니다).
- 확인 도구로 `tools/motor_bringup.py` 를 씁니다. 모터·엔코더·통신 중
  어디가 문제인지 구분해서 알려줍니다.

### 2. 한 번 겪은 문제들

| 문제 | 원인과 대처 |
|---|---|
| 센서 배선 후 소손 | 표만 보고 배선하지 말고 보드에 인쇄된 라벨을 직접 확인 |
| MQTT 로 보낸 값이 서버에 안 들어감 | ACL 규정에 안 맞는 발행은 에러 없이 조용히 버려집니다. `MQTT_CONTRACT.md` 의 ACL 부분부터 확인 |
| 센서값이 서버에 일부만 반영됨 | `messageId` 를 재사용하면 서버가 중복으로 보고 버립니다. 발행마다 새 UUID 사용 |
| 화면이 꺼진 채로 안 돌아옴 | 젯슨 화면 절전 중 nvidia-modeset 오류로 검은 화면이 됩니다. 절전은 이미 꺼둔 상태입니다. 새로 세팅할 경우 `JETSON_DISPLAY.md` 참고 |
| 화면 케이블을 전원 켠 채로 뽑아서 복구 안 됨 | 케이블을 먼저 연결하고 전원을 켤 것. 시연 중에는 화면 케이블을 건드리지 않기 |
| 젯슨 터미널에 여러 줄 붙여넣으면 중간 줄이 잘림 | 명령은 한 줄로 보내기 |
| 빌드했는데 코드가 안 바뀐 것처럼 동작함 | 소스가 아니라 설치된 파일이 실행되고 있을 수 있습니다. 안 되면 `rm -rf build install` 후 재빌드 |
| I2C 센서가 계속 인식 안 됨 | `write_quick` 방식은 젯슨(테그라)에서 지원하지 않습니다. `read_byte` 로 탐지 (`plant_sensors_node._probe` 참고) |
| BH1750 값이 항상 0 | 측정 전마다 전원 켜기(0x01) 명령이 필요합니다. 코드에는 이미 반영돼 있습니다 |
| `.bashrc` 에 줄을 추가했더니 기존 줄에 붙어버림 | 마지막 줄에 개행이 없던 것이 원인입니다. `printf '\n...'` 로 추가 |

### 3. 예전과 달라진 동작

- 로봇은 이제 귀가 알림을 받아야만 인사합니다 (티켓 351). 카메라 앞에
  서도 반응이 없다면 고장이 아니라 아직 알림을 못 받은 상태입니다.
  다음 명령으로 알림을 대신 보내 시험할 수 있습니다.
  ```
  ros2 topic pub -t 3 /mission/greet_command std_msgs/msg/String "{data: ''}"
  ```
- CI 설정을 바꿨습니다 (`requirements_ci.txt` 추가, torch 제거). 다음
  젠킨스 빌드가 정상적으로 통과하는지 확인이 필요합니다.

### 4. 비밀값

- 비밀번호나 토큰 같은 값은 저장소나 문서 어디에도 적어두지 않습니다.
  주소나 ID 같은 설정값만 저장소에 있고, 비밀값은 젯슨 `~/.bashrc` 의
  환경변수에만 있습니다.
- 사람에게 전달할 때는 메신저 개인 대화로 합니다. 파일로 모아두거나
  공개 채널에 올리지 않습니다 — 예전에 화면을 그대로 붙여넣다 값이
  노출된 적이 있습니다.
- 지금 쓰는 MQTT 비밀번호는 한 번 노출됐던 값이라, 시연 전에 서버팀과
  함께 교체하는 것을 권합니다.

### 실측이 필요한 값

로봇이 실제로 놓일 자리에서 재야 하는 값입니다. 지금은 legacy 코드에서
그대로 가져온 임시값이라 코드로 고칠 수 없습니다.

- **`light_lux` 임계값 (`potner_params.yaml`, 현재 200.0)** — 200lux 는
  평범한 실내 조명보다 어둡습니다. 이대로 두면 낮에도 계속 빛이
  부족하다고 판단해 일광욕 임무가 쉬지 않고 걸릴 수 있습니다. 식물이
  놓일 자리에서 낮/저녁/조명 끈 상태를 `ros2 topic echo /plant/lux
  --once` 로 재고 그 사이 값으로 바꾸세요.

| 완료 | 291·300·310·313·314·315~320·351, 그리고 초기 10개(43·49·51·91·92·105·106·233·240·38) |

## 서버·앱 팀에 요청해 둔 것

1. **`commandId` 왕복 처리** (명세 12절 3번, 서버팀이 가장 중요하다고
   표시한 항목). 이게 없으면 서버가 로봇이 대기 중인지 도착했는지
   구분하지 못해서, 대기 중인 로봇에게 급수 명령을 보낼 수 있습니다.
2. **`command/greet` 발행** (12절 7번 질문의 답). 로봇 쪽 처리는
   끝났고, 앱의 위치 감지와 서버 쪽 발행만 남았습니다.
3. **`command/speech`** — 서버가 만든 대사를 로봇에게 전달할 경로가
   명세에 없습니다. 지금은 정해진 인사말만 말합니다.

## 설계 규칙

1. 계산 로직은 ROS(rclpy)에 의존하지 않는 별도 모듈로 분리합니다. ROS
   없이도 CI 에서 테스트할 수 있는 유일한 방법이고, 노드 안에 로직을
   넣어뒀다가 버그를 두 번 놓친 적이 있습니다. 세부 규칙은
   [`CODE_STYLE.md`](CODE_STYLE.md) 참고.
2. 값이 여러 곳에 흩어져 있을 때(yaml, 노드 기본값, dataclass, 펌웨어
   상수) 이 값들을 서로 비교하는 테스트가 있습니다. 이 테스트가
   실패하면 테스트를 고치지 말고, 값이 어긋난 쪽을 고칩니다.
3. `src/potner_llm/` 과 `voice-chat-server/` 는 LLM 파트가 관리합니다.
   상의 없이 수정하지 않습니다. `speaker_node` 는 `shell=True` 를
   쓰지 않습니다 — 여기 들어오는 문장은 LLM 이 만든 외부 입력이기
   때문입니다.

## 첫날 순서 (제안)

1. `Robot-develop` 을 받아 `pytest tests/` 를 실행합니다 (289건 통과,
   ROS 없이도 가능합니다).
2. 젯슨에서 `ros2 launch potner_bringup robot.launch.py` 를 실행해
   표정·센서·MQTT 가 정상 동작하는 상태를 먼저 눈으로 확인해둡니다.
   이후 문제가 생겼을 때 비교할 기준이 됩니다.
3. 349 브랜치를 받아 모터 배선을 시작합니다. 코드보다 멀티미터
   측정부터 합니다 (위 1번 참고).
