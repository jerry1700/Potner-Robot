## ⚠️ 주의사항 — 이것만은 꼭

### 1. 모터 첫 배선 (다음 큰 작업)

- **반드시 `Robot-feature/motor-bringup/349` 브랜치에서 시작하세요.**
  머지 전까지 `Robot-develop` 의 바퀴 지름은 **전부 틀린 값**입니다
  (정답 0.060m — 실제 부품 60mm).
- **첫 회전은 개루프(`D` 명령)로.** 엔코더 배선이 틀린 채 폐루프(`V`)를
  돌리면 적분항이 차올라 **바퀴가 전속으로 돕니다.**
- **바퀴는 공중에 띄우고** 시작하세요. 방향이 반대면 책상에서 떨어집니다.
- BTS7960 의 **`R_EN`·`L_EN` 을 3.3V 에 묶으세요.** 안 묶으면 PWM 을 보내도
  안 돕니다 — 첫 시험에서 가장 흔한 막힘.
- **모터 전류(B+/B−/M+/M−)를 브레드보드에 올리지 마세요** (접점 한계 ~1A).
  나사 단자 직결 + 배터리 라인에 5A 퓨즈.
- 배선 전 멀티미터로: 팩 전압(11.1~12.6V), FIT0403 모터 선 한 쌍 찾기
  (저항 수 Ω), **엔코더가 3.3V 에서 도는지** (GPIO 34~39 는 3.3V 한계).
- 검증 도구: `tools/motor_bringup.py` — 모터/엔코더/통신 문제를 갈라서
  알려줍니다.

### 3. 동작이 예전과 다른 것

- **로봇은 이제 귀가 알림 없이는 인사하지 않습니다** (351). 카메라 앞에
  섰는데 조용하면 고장이 아니라 무장이 안 된 것:
  `ros2 topic pub -t 3 /mission/greet_command std_msgs/msg/String "{data: ''}"`
- **CI 의존성이 바뀌었습니다** (`requirements_ci.txt` 커밋, torch 제거).
  다음 젠킨스 실행이 초록인지 확인해 주세요.

### 4. 비밀값

- **비밀값은 저장소·문서 어디에도 없습니다.** 설정값(주소·ID)은 저장소가,
  비밀값은 젯슨 `~/.bashrc` 환경변수가 기억합니다.
- 사람 간 전달은 MM 개인 DM. 파일로 모으거나 공개 채널 금지 — 실제로
  화면 붙여넣기로 노출된 적이 있습니다.
- 현재 MQTT 비밀번호는 한 번 노출됐으므로 **시연 전 서버팀과 교체 권장.**

## 서버·앱 팀에 요청해 둔 것

1. **`commandId` 왕복** (명세 12절 3번, 서버팀 최중요 표시) — 없으면 서버가
   대기 중인 로봇에게 급수 명령을 보내 **물을 쏟습니다.**
2. **`command/greet` 발행** (12절 7번의 답) — 로봇 쪽은 완료, 앱 지오펜스 +
   서버 발행만 남음.
3. **`command/speech`** — TTS 대사 경로가 명세에 없음. 이게 없으면 로봇은
   고정 인사말만 말합니다.

## 설계 규칙 (세 줄)

1. **계산 로직은 rclpy 없는 순수 모듈에.** CI 가 검증할 유일한 방법 —
   노드 안에 두었다가 버그 두 번 놓쳤습니다. 스타일은 [`CODE_STYLE.md`](CODE_STYLE.md).
2. **드리프트 가드 테스트가 잡으면 테스트를 고치지 말고 나머지 곳을 마저
   고치세요** (yaml ↔ 노드 ↔ dataclass ↔ 펌웨어가 서로 대조됩니다).
3. **`src/potner_llm/` 과 `voice-chat-server/` 는 LLM 파트 소유** — 상의 없이
   고치지 마세요. `speaker_node` 는 절대 `shell=True` 금지 (LLM 문장 = 외부 입력).
